## Task A — `scripts/setup-linux.sh`

Script idempotente que:

1. Detecta libc: `ldd --version 2>&1 | grep -q "musl" && LIBC=musl || LIBC=glibc`
2. Localiza binário glibc via `bunx -e "import.meta.resolve('@anthropic-ai/claude-agent-sdk-linux-x64/claude')" 2>/dev/null || echo ""`
   - Fallback: `find ~/.bun ~/.npm ~/.local -name 'claude' -path '*linux-x64/claude' 2>/dev/null | head -1`
3. Se encontrou: cria symlink ou copia para `~/.clawde/bin/claude` (mkdir -p primeiro).
4. Atualiza `~/.clawde/config/clawde.toml` adicionando `claude_executable_path = "~/.clawde/bin/claude"` se ainda não presente.
   - Usar `grep -q claude_executable_path` antes para idempotência.
5. Imprime resultado: `setup-linux.sh: OK — glibc binary at ~/.clawde/bin/claude`.

**Requisitos:**
- `set -euo pipefail`.
- Exec bit: `100755` no git (`git update-index --chmod=+x scripts/setup-linux.sh`).
- Funciona em Ubuntu 22.04 + 24.04, Debian 12, RHEL 9 (glibc systems).
- Idempotente: rodar duas vezes = mesmo estado.
- Não instala nada globalmente sem permissão explícita.

**Teste:** `tests/unit/sandbox/systemd.test.ts` existente pode ser extendido para verificar
exec bit do setup script. Ou teste separado em `tests/integration/setup-linux.test.ts` que:
- Cria tmpdir, simula node_modules structure com binário fake.
- Roda script com variáveis overrides.
- Verifica que `~/.clawde/bin/claude` (redirected via env) existe e é executável.

## Task B — `clawde-deferred-check.service` + `.timer`

Novos arquivos em `deploy/systemd/`:

**`clawde-deferred-check.service`:**
```ini
[Unit]
Description=Clawde deferred task check — processa tasks com not_before expirado

[Service]
Type=oneshot
WorkingDirectory=%h/.clawde
EnvironmentFile=-%h/.clawde/config/clawde.env
ExecStart=%h/.clawde/dist/clawde-worker

# Hardening idêntico ao worker (BEST_PRACTICES §10.4)
PrivateTmp=yes
ProtectHome=read-only
ProtectSystem=strict
NoNewPrivileges=yes
PrivateDevices=yes
ProtectKernelTunables=yes
ProtectKernelModules=yes
ProtectControlGroups=yes
LockPersonality=yes
MemoryDenyWriteExecute=yes
RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6
RestrictNamespaces=yes
RestrictRealtime=yes
RestrictSUIDSGID=yes
SystemCallArchitectures=native
SystemCallFilter=@system-service
SystemCallFilter=~@privileged @resources
CapabilityBoundingSet=
AmbientCapabilities=

ReadWritePaths=%h/.clawde

[Install]
WantedBy=default.target
```

**`clawde-deferred-check.timer`:**
```ini
[Unit]
Description=Clawde deferred task check agendado (a cada 30 minutos)

[Timer]
OnBootSec=5min
OnUnitActiveSec=30min
Unit=clawde-deferred-check.service
Persistent=true

[Install]
WantedBy=timers.target
```

**Nota:** `OnBootSec=5min` garante que tasks deferidas antes de um reboot são processadas
rapidamente após o sistema voltar.

**Testes:** adicionar em `tests/unit/sandbox/systemd.test.ts`:

## Task C — `BEST_PRACTICES.md` — comportamentos validados (#45)

Adicionar nova seção no final de `BEST_PRACTICES.md` (ou em seção §12 "Operação em produção"):

```markdown
## §12 — Comportamentos validados em produção (WSL2 Ubuntu 24.04)

Validados em 2026-05-02 com Clawde 0.0.1, Bun 1.3.13, 8 tasks, 274 msgs.

### Reconcile de lease expirado
Quando worker é terminado com task em andamento, na próxima invocação:
- `task_run` zombie recebe `status=abandoned`
- Novo `task_run` é criado com `attempt_n=attempt+1`
- Task volta para fila e é processada normalmente

### Quota gate com `not_before`
Quando quota esgota, worker defere tasks corretamente com `not_before`
apontando para o reset da janela. Worker sai limpo com `exit_reason=deferred`.

### Health endpoint reflete estado da quota
`GET /health` retorna `{"ok":false,"reason":"quota_exhausted","details":"..."}` quando
quota está esgotada. Útil para monitoramento externo.

### Receiver estável
`clawde-receiver.service` permanece `active (running)` durante múltiplos ciclos de
start/kill/reconcile do worker, quota exhaustion e SIGKILL no worker.
Nenhum restart do receiver foi necessário nos testes de resiliência.

### Nota operacional
Tasks deferidas não têm auto-trigger após reset de quota até ativação do
`clawde-deferred-check.timer` (issue #44, fix na Fase 2).
```
