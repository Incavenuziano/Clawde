# Fase 3 — `clawde result` command

**Owner:** Claude (implementer)
**Reviewer:** Codex (review after PR opened)

**Wave:** 2 (pode começar em paralelo com Fase 2, não depende dela)

## Problema (#42)

Quando agente responde principalmente via tool calls (Glob, Grep, Read, Edit),
`agentResult.finalText` é vazio. `task_runs.result` fica `NULL`. O conteúdo real
existe no JSONL da sessão (`~/.claude/projects/<hash>/<uuid>.jsonl`).

## Escopo

Duas mudanças complementares:

### Task A — Enrichment em `runner.ts`

Em `src/worker/runner.ts`, ao finalizar a task, ao invés de salvar só `finalText`:

```typescript
// Atual
result: agentResult.finalText.length > 0 ? agentResult.finalText : null

// Proposto
// Concatenar TODOS os blocos de texto de mensagens assistente no stream
// (não só finalText que pode ser vazio em tasks tool-heavy)
const fullText = extractFullAssistantText(agentResult);
result: fullText.length > 0 ? fullText : null
```

`extractFullAssistantText` deve iterar `agentResult.messages` (ou equivalente)
e concatenar blocos de texto de mensagens com `role=assistant`.

**Verificar na API do SDK:** qual propriedade contém o histórico de mensagens.
Se `agentResult.messages` não estiver disponível, usar `agentResult.finalText`
com fallback para leitura do JSONL (Task B).

**Importante:** se o SDK não expõe mensagens intermediárias, a Task A é no-op
e Task B cobre via JSONL read.

### Task B — `clawde result <task-id>` CLI command

**Arquivo:** `src/cli/commands/result.ts` (novo)

Fluxo:
1. `openDb(dbPath)`, busca `tasks.id = taskId`.
2. Busca `task_runs` mais recente (status=succeeded ou failed).
3. Se `task_run.result` não-NULL: imprime direto. Done.
4. Se `task_run.result` IS NULL e `task_run.session_id` não-NULL:
   - Resolve path do JSONL: `~/.claude/projects/<hash>/sessions/<session_id>.jsonl`
   - Onde `<hash>` é derivado do working dir da task ou fallback para `find ~/.claude/projects -name "<session_id>.jsonl"`.
   - Lê JSONL, filtra entries com `type=message, role=assistant`, extrai `content[].text`.
   - Concatena e imprime.
5. Se nada encontrado: imprime warning e exit 1.

```typescript
export interface ResultOptions {
  readonly taskId: number;
  readonly dbPath: string;
  readonly format: OutputFormat;
  readonly claudeProjectsDir?: string; // override para testes
}

export async function runResult(options: ResultOptions): Promise<number>
```

**Wiring em `src/cli/main.ts`:**
```
result <task-id>       Exibe resultado de uma task (text ou JSON)
```

**Testes** em `tests/integration/result-cmd.test.ts`:
- Task com `result` não-NULL: imprime direto.
- Task com `result` NULL e session JSONL mockado: extrai texto correto.
- Task ID inexistente: exit 1 + stderr error.
- Task sem session_id: exit 1 + mensagem sugestiva.

### Task C — Registro no help text

Adicionar em `HELP_TEXT` de `src/cli/main.ts`:
```
result <task-id>       Exibe resultado de uma task (busca no DB e JSONL de sessão)
```
