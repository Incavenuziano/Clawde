# Fase 1 — SDK binary path resolution

**Owner:** Claude (implementer)
**Reviewer:** Codex (review after PR opened)
**Branch:** `fix/sdk-binary-path` — criar a partir de `main`

## Problema

O `@anthropic-ai/claude-agent-sdk` resolve o binário nativo via `import.meta.dir`,
que aponta para o diretório do bundle (`~/.clawde/dist/`) em produção. Em Ubuntu/Debian,
o binário musl é selecionado por erro. Resultado: worker falha silenciosamente.

**Issues:** #41 (musl vs glibc) + #43 (bundle perde caminho)

## Escopo desta fase

Adicionar config `worker.claude_executable_path` e passar para o SDK como
`pathToClaudeCodeExecutable`. **Não inclui** o setup script (Fase 2, Codex).

## Tasks

### Task A — Config schema (`src/config/schema.ts`)

Adicionar campo opcional em `WorkerSchema`:

```typescript
claude_executable_path: z.string().optional(),
```

Adicionar ao `config/clawde.toml.example`:

```toml
# Opcional: apontar explicitamente para o binário glibc quando worker
# é executado a partir de bundle externo ao node_modules.
# Necessário em Ubuntu/Debian se o worker for deployado em ~/.clawde/dist/.
# Exemplo: claude_executable_path = "/usr/local/bin/claude"
#          ou "$HOME/.clawde/bin/claude" (via scripts/setup-linux.sh)
# claude_executable_path = ""
```

### Task B — Wire no worker (`src/sdk/client.ts` ou `src/worker/runner.ts`)

Quando `config.worker.claude_executable_path` estiver setado, passar para o SDK:

```typescript
const agentOptions: AgentRunOptions = {
  // ... opções existentes ...
  ...(config.worker.claude_executable_path
    ? { pathToClaudeCodeExecutable: config.worker.claude_executable_path }
    : {}),
};
```

Verificar exatamente onde `new RealAgentClient()` é instanciado e como `pathToClaudeCodeExecutable`
é aceito pela versão atual do SDK (`@anthropic-ai/claude-agent-sdk@0.2.123`).

### Task C — Teste

Adicionar em `tests/unit/config/` ou `tests/unit/worker/` um teste que:
- Valida que config com `claude_executable_path` não-vazio parseia sem erro.
- Valida que config sem o campo parseia com default `undefined`.

Não é necessário testar o wire end-to-end (requereria mock do subprocess).

### Task D — Documentação

Em `README.md` (Quick start section) ou novo `docs/DEPLOY-LINUX.md`:

```markdown
## Ubuntu/Debian — binário glibc

O worker precisa do binário glibc do SDK. Execute o setup script (incluído no repo):

    bash scripts/setup-linux.sh

Isso instala o binário em `~/.clawde/bin/claude` e configura `~/.clawde/config/clawde.toml`
automaticamente. Detalhes: issues #41 e #43.
```
